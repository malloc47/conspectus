## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Starting a mux and detaching right away leaves Conspectus showing it as not running, and killing a mux can leave it showing as running until a manual refresh. The post-action refresh and the refresh command return before the mux class has been re-probed, or use a cached probe inside its interval. The smoke script saw the same effect: a new mux needed several refresh --class mux calls to appear.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 After any action that starts, stops, or renames a mux, and after returning from attach, the refresh re-probes muxes and publishes the result before the screen updates
- [ ] #2 refresh --class mux and the TUI refresh do not return until the re-probe is reflected in the snapshot they return
- [ ] #3 A test with a delayed backend shows start-then-detach and kill both reflect the right state on the first refresh
- [ ] #4 The scratch smoke script sees a new or killed mux after a single refresh --class mux
<!-- AC:END -->
