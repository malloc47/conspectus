## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Starting a mux and detaching right away leaves Conspectus showing it as not running, and killing a mux can leave it showing as running until a manual refresh. The post-action refresh and the refresh command return before the mux class has been re-probed, or use a cached probe inside its interval. The smoke script saw the same effect: a new mux needed several refresh --class mux calls to appear.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 After any action that starts, stops, or renames a mux, and after returning from attach, the refresh re-probes muxes and publishes the result before the screen updates
- [x] #2 refresh --class mux and the TUI refresh do not return until the re-probe is reflected in the snapshot they return
- [x] #3 A test with a delayed backend shows start-then-detach and kill both reflect the right state on the first refresh
- [x] #4 The scratch smoke script sees a new or killed mux after a single refresh --class mux
<!-- AC:END -->

## Definition of Done
<!-- DOD:BEGIN -->
- [x] #1 `just check` passes, or `git diff --check` for docs-only changes
- [x] #2 Docs and ADRs are updated when behavior, architecture, or workflow change
<!-- DOD:END -->

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Root cause was a 5 second tmux listing cache hit by every refresh path. Mux-affecting refreshes clear it, the daemon publishes before replying, and returning from attach re-probes until the state settles. Verified by scripted-backend tests, daemon tests, a real-tmux test, and the scratch smoke checks.
<!-- SECTION:FINAL_SUMMARY:END -->
