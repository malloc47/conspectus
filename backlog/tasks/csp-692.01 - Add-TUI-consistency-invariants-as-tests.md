## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Each defect found in manual testing was a one-off, but they cluster into invariants (the same gesture does the same thing in every view, every mutating action ends in a refresh, menus depend on the entity and not the view, unfocused panes show no highlight, user text never cites developer artifacts). Tests that assert those invariants across all views and row kinds catch the next instance, where per-bug tests don't. Land them first, marked expected-failing per defect, so each fix visibly flips one.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 A cross-view parity test drives Enter, p, v, and . on every row kind in every view and asserts the same effect as the canonical view for that entity
- [ ] #2 A lifecycle test asserts every effect that changes mux, slot, history, or worktree state freezes the selected row, refreshes, and applies the follow-focus rule, and fails when a new mutating effect is added without declaring its policy
- [ ] #3 A menu test asserts the entries offered for an entity are identical whichever view opens the menu, and that entries with nothing meaningful to show are hidden
- [ ] #4 A focus test asserts accelerators act on the right pane's entity when it has focus and on the selected row otherwise
- [ ] #5 A rendering test asserts aligned columns, chips, glyphs, and dimming are uniform across views, that an unfocused pane shows no highlighted row, and that regrouping resets scroll
- [ ] #6 A text-hygiene test fails when user-visible TUI or CLI text names an ADR, backlog ID, or design document
<!-- AC:END -->

## Definition of Done
<!-- DOD:BEGIN -->
- [ ] #1 `just check` passes, or `git diff --check` for docs-only changes
- [ ] #2 Docs and ADRs are updated when behavior, architecture, or workflow change
