## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The pin edit form shows a second set of labels on the right (pin name, snapshot, history) with no explanation, those labels shift by one character when the selection moves, the cwd field shows a stray h or a will override note that scrolls off the right edge, and it is unclear what inherit means. Text must never shift on selection or be pushed outside a modal.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Each field row shows label, value, and a fixed-width source tag inside the modal, with long values truncated, never overflowing
- [x] #2 Moving the selection changes only styling, never the position of any text
- [x] #3 The form explains in plain words that an empty field follows the running or last-known value and typing sets a value kept with the pin
- [x] #4 A generic test renders every modal and form at narrow and wide sizes and asserts no clipped text and no layout change on selection
<!-- AC:END -->

## Definition of Done
<!-- DOD:BEGIN -->
- [x] #1 `just check` passes, or `git diff --check` for docs-only changes
- [x] #2 Docs and ADRs are updated when behavior, architecture, or workflow change

Rebuilt the pin edit form on a fixed grid with a source tag, a plain explanation, and a focused-field hint; selection moves no text; a generic layout test covers every modal at four widths and two heights.
