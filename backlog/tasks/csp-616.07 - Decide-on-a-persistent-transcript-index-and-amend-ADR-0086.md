## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Deferred by operator decision (2026-10-16): the MVP scans on demand, but a persistent full-text index is wanted eventually, so search stays fast as transcript history grows (e.g. when Claude Code's transcript cleanup is extended and the corpus reaches gigabytes). Start this when the on-demand scan misses the latency budget or exceeds the corpus-size threshold recorded in CSP-616.01 and CSP-616.03, or when the operator asks.

An index stores transcript payload on disk, which today's rules forbid: ADR 0086 limits Tier 2 content to the current session, and CLAUDE.md and ADR 0087 say Conspectus never persists payload and never performs background mutation. The ADR must amend both explicitly rather than work around them.

Questions to settle:
- Engine: compare SQLite FTS5 (check that the bundled `rusqlite` build enables it, which would add no new dependency), tantivy (a new dependency), and a custom inverted index. Weigh query features, index size, incremental updates, and maintenance. Evaluate the heavier options fully where they serve the known need for scale.
- Location and protection: `$XDG_CACHE_HOME` vs `$XDG_STATE_HOME`, 0600 permissions, rebuildable, and outside project trees.
- Consent: opt-in config, defaulting to off.
- Freshness and purge: how the index tracks appended, rewritten, and deleted transcripts, and a way to wipe it on demand.
- Build trigger: operator-initiated, or a daemon background job (which needs an ADR 0087 amendment).
- Fallback: the on-demand scan stays authoritative whenever the index is missing, stale, or disabled.
