## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
- Why: ADR 0112 §1–2. A RuntimeProcess node and every process-ID field (`pid`, `parent_pid`, `root_pane_pid`, `active_pane_pid`) should show the processes running there, which is how the operator sees what a pane or harness actually spawned.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 A RuntimeProcess node previews its process tree, with each process's command and working directory
- [x] #2 A process-ID field previews the tree rooted at that process
- [x] #3 A process that has exited previews "no longer running"
- [x] #4 The preview reads `/proc` only and degrades to an unavailable state where `/proc` does not exist
<!-- AC:END -->

## Definition of Done
<!-- DOD:BEGIN -->
- [x] #1 `just check` passes, or `git diff --check` for docs-only changes
- [x] #2 Docs and ADRs are updated when behavior, architecture, or workflow change
<!-- DOD:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. A `/proc` reader with an injectable root: children by parent from each `stat`, then each process's `cmdline` and `cwd`.
2. A `Process(pid)` source for RuntimeProcess nodes and `FieldValue::Process` on pid fields.
3. Tests against a fake `/proc` tree and the real one.
<!-- SECTION:PLAN:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
- No existing discovery code read process trees from `/proc`, so the reader is new and lives with the preview loaders.
- Caps: 200 processes, 16 levels, 200 characters per command line; kernel threads and zombies show `[comm]`.
- Process trees aren't conversation or terminal content, so they show under `--no-live-preview`.
<!-- SECTION:NOTES:END -->

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
RuntimeProcess nodes and pid fields (`pid`, `parent_pid`, `root_pane_pid`, `active_pane_pid`) preview the process tree rooted there, each process with its command and working directory, read from `/proc` only; an exited process previews "no longer running" and a system without `/proc` an unavailable state. Verified with `just check`, tests against a fake `/proc` tree and the real one, and a live snapshot of a harness process's Related row.
<!-- SECTION:FINAL_SUMMARY:END -->
