## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
On-demand search has to cover every session quickly without an index, and the TUI needs results while the scan is still running, with each new keystroke abandoning the previous scan. This story turns a snapshot plus a query into a stream of results by resolving each agent session's transcript through the adapter registry and running the CSP-616.02 matcher.

Context:
- Session list: agent-session nodes in the snapshot. Transcripts come from `HarnessAdapter::transcript_source` and `transcript_parser`; sessions whose harness has no parser are skipped and counted.
- Measured 2026-10-16: about 320 MB of transcripts, a 50 ms raw byte scan, and about 0.9 s to parse everything single-threaded. A cheap prefilter that skips files which can't match keeps the parse to the candidates. The prefilter must not miss matches whose text is JSON-escaped on disk; the rule comes from CSP-616.01. opencode stores sessions in SQLite, so its prefilter or full read differs from the JSONL harnesses.
- No new dependencies (std threads), and nothing is persisted (ADR 0086). One unreadable or malformed transcript is skipped and counted; it never fails the search.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Searching a snapshot streams results while it runs and reports progress (sessions scanned, total, skipped)
- [ ] #2 Starting a new search or dropping the handle stops the running scan promptly
- [ ] #3 The prefilter never drops a match that a full parse finds, including JSON-escaped text, verified against a fixture corpus covering every supported harness
- [ ] #4 Unreadable, malformed, or parserless sessions are counted and skipped without failing the search
- [ ] #5 A benchmark against a corpus of realistic size is recorded, alongside the revisit thresholds from CSP-616.01
