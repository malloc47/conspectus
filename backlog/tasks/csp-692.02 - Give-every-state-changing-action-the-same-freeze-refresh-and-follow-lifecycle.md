## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Enter on a gone row rebuilds without attaching or refreshing, a detach or kill returns to the TUI without the frozen spinner row and forced refresh the old launch had, pinning a PR blanks the PR list (the pin refresh path skips forge discovery), and rebuilding from History leaves the operator hunting for the new mux. These are regressions from the behavior before the slot work.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Enter on a gone mux, gone history record, or gone slot rebuilds, attaches, and refreshes, matching the old start-and-attach behavior
- [x] #2 Returning from attach (detach or kill) freezes the selected row with a spinner and forces a refresh, as before
- [x] #3 Every state-changing gesture (pin, unpin, edit, rename, retarget, rebuild, forget, clean up, launch) refreshes without dropping any view's data, including PRs
- [x] #4 When an action makes a row leave its view (a History record that comes back as a live mux), focus moves to the view where the entity now lives with its row selected
- [x] #5 p pins the selected row in one keypress in every view
<!-- AC:END -->

## Definition of Done
<!-- DOD:BEGIN -->
- [x] #1 `just check` passes, or `git diff --check` for docs-only changes
- [x] #2 Docs and ADRs are updated when behavior, architecture, or workflow change
<!-- DOD:END -->

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Key-bound writes run on the live executor; Enter on gone muxes, records, and unstarted pins rebuilds and attaches; all row kinds freeze with a spinner and refresh after attach; every state-changing effect honors one declared refresh policy and no longer blanks the PR list; focus follows the entity to its new view. Covered by lifecycle and action tests.
