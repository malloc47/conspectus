## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
A content-search hit is only useful if opening it lands on the matching turn. The native viewer today opens at the end of the transcript, with no find and no way to jump to a turn (`ViewerMsg` covers scrolling, jumps to start and end, and the tool, thinking, and aborted toggles). This story adds find inside the viewer and lets callers open it at a match, so the `/` contents scope (CSP-616.06) and the viewer share one experience.

Context:
- Find uses the CSP-616.02 matcher so the viewer and search agree on what matches.
- A hit can sit in content the viewer hides by default: tool output (the `t` cycle), thinking (`T`), or aborted turns (`I`). Decide whether jumping to such a hit reveals that one turn or switches the toggle, and say so in the viewer help.
- Key bindings must be discoverable in the viewer help overlay (`?`), consistent with the TUI's menu-first convention.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Vetted: depends on CSP-703 (viewer help generated from the key table). ViewerMsg is Copy so the find prompt needs its own mode and key table (MODAL_CONVENTION row, overlay keymap hygiene), with a hand-rolled line buffer since the viewer may not import tui widgets; add a turn_starts map to the render cache (the inline preview shares body_lines; Summary tool detail collapses runs); find matches the raw body with the shared matcher and highlights best-effort on rendered lines; a hit in hidden tool/thinking content flips that toggle and says so in the footer; ExecSpec::ViewSession gains an optional open-at target (about 10 match sites plus lifecycle); the viewer re-matches near the stored turn index if the live transcript changed. CSP-339 is the same feature and is closed as superseded.
