## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
- Why: the preview-per-node direction is a TUI model decision, so it needs an ADR before code depends on it. The operator wants to walk through each node kind and choose what, if anything, it previews. Directory contents for a working directory came up as one example when this was filed.
- Context: Preview today has a single source, the mux capture cache in `src/tui/preview.rs`, keyed by `MuxSessionId`. The native viewer (`src/viewer/`) already parses and renders transcripts for full-screen use.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 An ADR records, for each of the ten node kinds (`Repo`, `Checkout`, `Workspace`, `AgentSession`, `MuxSession`, `Pin`, `RuntimeProcess`, `Branch`, `Fork`, `ForgePr`), what Preview shows, or that it shows nothing
- [ ] #2 The ADR defines how a node exposes its preview capability, so adding a preview for another kind does not route through the mux capture path
- [ ] #3 The ADR decides what a muxed agent session previews by default and whether its pane capture stays reachable
- [ ] #4 The ADR states how previews stay within ADR 0086 (no persisted payload) and ADR 0087 (read-only)
- [ ] #5 The ADR says whether `CSP-213`, `CSP-214`, and `CSP-171.03` are superseded, and those tasks are updated to match
- [ ] #6 `docs/design.md` reflects the decision where it changes the TUI model
<!-- AC:END -->
