## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
- Why: the preview-per-node direction is a TUI model decision, so it needs an ADR before code depends on it. The operator wants to walk through each node kind and choose what, if anything, it previews. Directory contents for a working directory came up as one example when this was filed.
- Context: Preview today has a single source, the mux capture cache in `src/tui/preview.rs`, keyed by `MuxSessionId`. The native viewer (`src/viewer/`) already parses and renders transcripts for full-screen use.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Research (done): the Preview zone has two modes. With the explorer cursor on a Related link row it shows the neighbor's summary, edge, and evidence (ADR 0107). Otherwise it falls back to `selection_preview_body` in `src/tui/ui/preview_pane.rs`, which knows only the tmux pane capture (cached per `MuxSessionId` in `src/tui/preview.rs`), a session's one-line `last_message_preview`, and pin diagnostics; every other row says "no preview for this row". Node field rows such as `cwd` have no preview of their own.
2. Walk the operator through each node kind and the cross-cutting choices: what a muxed session shows by default, what a Related row previews, and whether field rows preview their value.
3. Write the ADR: the per-kind mapping for all ten node kinds, how a node exposes a preview source, privacy gating under `--no-live-preview` (ADR 0023, ADR 0086), read-only sources (ADR 0087), and the fate of `CSP-213`, `CSP-214`, and `CSP-171.03`.
4. Update `docs/design.md` and the superseded tasks to match, then file one implementation subtask per node kind that gains a preview (with the operator's approval).
<!-- SECTION:PLAN:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Operator decisions (2026-10-12): a session in tmux previews its transcript by default, with the live pane one choice away in the controls overlay as one global, remembered setting; a Related row shows its edge and evidence as a header above the neighbor's own preview; every field row previews its value by value type (approved mapping in ADR 0112 §2); Checkout previews `git status` above a listing and Repo previews recent commits and remotes; the whole recent-turns chain is superseded.
Correction made while writing the ADR: the PR's `pr` and `url` fields name the PR itself (`owner/repo#number`, its own link), so they preview the focused node, not another node.
Backlog changes: archived `CSP-207`–`CSP-210` and `CSP-213`–`CSP-215` with notes; `CSP-171.03` now depends on `CSP-585.02`; `CSP-246` notes the viewer parser as its transcript source; `CSP-211` retitled to an aider parser for the viewer. `backlog doctor` is clean.
