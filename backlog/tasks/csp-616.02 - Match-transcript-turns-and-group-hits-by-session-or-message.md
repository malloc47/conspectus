## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The core of content search, shared by the CLI, the `/` overlay, and the viewer's find: given a query, a content scope, and a grouping, find matches in one parsed `TranscriptDocument` and turn them into ranked results. It is kept pure, with no I/O, so the matching rules are tested once and every surface agrees on what counts as a hit.

Context:
- The existing `/` matcher (`src/tui/search.rs`) is a case-insensitive substring match with `snippet_around` for windowed snippets. Reuse or generalize it rather than adding a second matcher.
- Content scope selects turn kinds: messages by default, with tool calls and output, and thinking, as opt-ins (operator decision 2026-10-16). Per-session grouping is the default; per-message grouping is the alternative.
- Snippets are payload on display, so ADR 0086 Tier 2 applies: they are length-capped and normalized (whitespace collapsed, no control sequences).
- The `[search]` config section holds the default grouping and content kinds, as settled in CSP-616.01.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Matching a document returns per-message hits with turn index, role, kind, timestamp, and a capped, normalized snippet with the highlighted range
- [ ] #2 Per-session grouping aggregates hits into hit count, best snippet, and latest hit time, ranked as the ADR specifies
- [ ] #3 Content scope filters which turn kinds are searched; by default only user and assistant messages match
- [ ] #4 A [search] config section sets the default grouping and content kinds, and invalid values produce config diagnostics
- [ ] #5 Unit tests cover case folding, non-ASCII text, snippet caps, kind filtering, and ranking in both groupings
<!-- AC:END -->
