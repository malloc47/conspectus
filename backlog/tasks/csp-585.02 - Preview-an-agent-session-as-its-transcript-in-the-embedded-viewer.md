## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
- Why: the first node-specific preview the operator asked for. Selecting a session today shows the tmux pane it runs in, or nothing when it has none, while the conversation is what tells sessions apart. The embedded session viewer (ADR 0052) already renders transcripts full screen; this brings an inline version of it into the Preview area.
- Blockers: the design subtask, which decides how a node exposes its preview and what a muxed session shows by default.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Viewer: expose the inline body render (`viewer::widget::body_lines`) sharing `draw_body`'s per-width render cache, so the preview and the full-screen modal compose transcripts the same way. Stays inside the ADR 0052 extraction boundary.
2. Bridge: `viewer_bridge::load_transcript` returns the parsed document, or why not: unavailable (no native parser for the harness, transcript file not found) versus failed (I/O, malformed).
3. Preview cache (ADR 0112 §5): `PreviewSource { Pane(mux), Transcript(session) }` keys a generalized `PreviewStore` with loading and stale marks and a cap on cached transcripts. `Msg::SetMuxPreview` becomes `Msg::SetPreview`. A pure resolver maps the selection to its source: sessions to their transcript (the pane when `session_preview = pane` and the session is in tmux), mux rows and candidates to the pane, pins unchanged until `CSP-585.08`.
4. Loading: `refresh_mux_preview_if_needed` becomes `refresh_preview_if_needed`, reloading on selection change, `r`, and a tmux hand-off return while showing the previous content. Live mode parses transcripts on a worker thread and drains results like discovery; scenario and snapshot modes load synchronously. Pane capture keeps its synchronous path into the shared cache.
5. Rendering: a transcript sits bottom-anchored with the newest turns in view; `J`/`K` scroll back through history, with a scrollbar; the failure banner still leads the zone. States: loading, unavailable with its reason, failed, and "no turns yet". `--no-live-preview` hides the transcript and falls back to the session's one-line `last_message_preview`.
6. Session preview choice (ADR 0112 §4): `SessionPreview { Transcript, Pane }`, `[tui] session_preview`, remembered in `tui-state.json`, a "Session preview" controls-overlay section, no key binding. Mirrors `preview_wrap`.
7. Tests: source resolution, the cache, bridge reasons, rendering and scrolling, the toggle and its persistence; the first binary-level `tui --snapshot` test, covering a muxed session, an un-muxed session, and an unreadable transcript.
8. Docs: `docs/operations.md` config sample, `docs/design.md` Preview section, help text where it names the preview.
<!-- SECTION:PLAN:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Decisions made while building:
- `--no-live-preview` shows the privacy banner for every session. Plan step 5 had it fall back to the one-line `last_message_preview`; reversed because ADR 0112 §6 hides conversation content, the old behavior already bannered sessions in tmux, and that line still shows in the session's fields.
- Pane captures stay synchronous through the executor's mux op; only transcripts load on a worker. A worker panic ends the load as failed so `r` can retry.
- A transcript's scroll offset counts up from its newest line, so `J`/`K` keep their direction. The Preview scroll now resets whenever the selection or explorer cursor moves; before, it carried over between rows.
- `r` now re-reads the selected preview, pane captures included (before, it only rediscovered).
- The cache keeps the 8 most recently loaded transcripts.
- Snapshot mode reads the selection's transcript before its frame and still leaves panes uncaptured.
- With the explorer drilled into a neighbor, the Preview still follows the left selection; `CSP-585.03` moves it to the focused node.
- Fixed a viewer wrap bug the inline preview exposed (`4da7a31`): a word that missed a line's last cells overflowed it, which the full-screen viewer silently clipped.
Follow-ups filed: `CSP-587` (the README frame and showcase fixture have no transcripts to preview), `CSP-588` (search can't find a session by the id its row shows).
<!-- SECTION:NOTES:END -->

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Selecting an agent session previews its transcript, rendered by the native viewer and bottom-anchored on its newest turns, in or out of tmux; `J`/`K` scroll back through it, and an unreadable transcript says why. Built the shared preview mechanism ADR 0112 §5 describes: a source resolved from the selection keys an in-memory cache with loading and stale marks, transcripts parse on a worker thread, and a source reloads on selection change, `r`, and a tmux hand-off return. A remembered "Session preview" controls-overlay choice (`[tui] session_preview`) switches sessions in tmux to the pane; mux rows keep the pane. Also fixed a viewer wrap overflow. Verified with `just check` (2,243 tests), including the first binary-level `tui --snapshot` test for a session in tmux, one outside it, and one whose transcript is gone, plus a live snapshot against this machine's sessions.
