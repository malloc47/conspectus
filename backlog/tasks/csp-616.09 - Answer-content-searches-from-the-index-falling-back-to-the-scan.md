## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Deferred behind CSP-616.08. Once an index exists, the CLI, the `/` contents scope, and the viewer should query it instead of scanning, without changing results. Only latency should change. The on-demand scan remains the fallback when the index is missing, stale, or disabled.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Search uses the index when it is enabled and fresh, and the scan otherwise, with identical results on a fixture corpus
- [ ] #2 A stale or missing index falls back to the scan without errors, and the TUI shows which source answered
- [ ] #3 A benchmark compares index and scan latency on a large corpus
<!-- AC:END -->

## Definition of Done
<!-- DOD:BEGIN -->
- [ ] #1 `just check` passes, or `git diff --check` for docs-only changes
- [ ] #2 Docs and ADRs are updated when behavior, architecture, or workflow change
<!-- DOD:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
TUI framework update (2026-10-31, CSP-766): content search is now a `tuikit::palette::Palette` with a debounced slow provider (`src/tui/widgets/search.rs`, ADR 0174 and 0175), and the Search view lists its hits through a column schema (ADR 0185). The palette words a slow provider's progress (`palette::Progress`) in its status row, which is where "the TUI shows which source answered" (AC #2) can go without new chrome. The viewer still opens a hit through `src/tui/viewer_bridge.rs`.
<!-- SECTION:NOTES:END -->
