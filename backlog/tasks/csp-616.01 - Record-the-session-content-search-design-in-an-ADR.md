## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Content search reads transcript payload for every session, which ADR 0086 places in Tier 2 only under specific conditions, and it adds a new kind of scan that the TUI, the CLI, and the viewer will share. The decisions the operator made on 2026-10-16 (see the parent CSP-616) need recording, and the remaining design questions below need answers before implementation starts.

Questions to settle (recommended answers in brackets):
- ADR 0086 placement: the query is the operator gesture, and hits and snippets live in memory only for the life of one overlay or CLI invocation. They are never written to disk, never stored in the graph or `graph.bin`, and never sent over the daemon socket. Snippets are capped and normalized. [Tier 2 reader, documented here as ADR 0086 requires.]
- Where the scan runs: [in the TUI or CLI process, not the daemon. The session list comes from the snapshot, and transcripts are read directly from harness state.]
- Corpus: [agent-session nodes in the snapshot whose adapter provides a transcript parser. Coverage grows as parsers land, e.g. opencode 2.x (CSP-604) and Pi (CSP-613); aider stays out until CSP-211.] Do Claude Code sidechain or subagent transcripts count?
- Filters: does the contents scope honor the view's active filters, as `/` does under ADR 0031, or span every session? [All sessions by default, with a toggle to stay within the current filters.]
- Query semantics: [case-insensitive substring, matching `/`.] Decide on smart-case, multiple terms ANDed, and quoted phrases.
- Content kinds: how viewer `TurnKind`s map to the searchable kinds (messages, tool calls and output, thinking), whether aborted turns count, and the `[search]` config schema for the default grouping and kinds.
- Ranking for per-session and per-message grouping (hit count, recency).
- Concurrency and cancellation, under the constraint of no new dependencies: std threads, with a new query cancelling the running scan. Include the rule that keeps a byte-level prefilter from missing matches whose text is JSON-escaped on disk (quotes, backslashes, non-ASCII, newlines).
- When to revisit a persistent index: a latency budget (e.g. results start within 300 ms and finish within 2 s) or a corpus size that triggers the follow-up index subtasks.
