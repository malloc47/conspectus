# ADR 0113: README Screenshots From The Showcase Fixture

## Status

Accepted. Builds on ADR 0067 (TUI snapshots), ADR 0068 (snapshot
fixtures), and ADR 0070 (showcase scenario).

## Context

The README shows one monochrome text frame of the TUI, rendered by
hand from the showcase fixture. Readers deciding whether to try
Conspectus get no sense of its color, layout, or previews, and the
frame goes stale silently. With node-specific previews (ADR 0112) the
Preview zone is the most telling part of the screen, but the showcase
fixture only carries a graph: its paths (`/fixture/...`) point
nowhere, so every transcript, listing, and git preview reads
"unavailable". Relative ages ("12d ago") also drift from the fixture's
anchor time with every render.

## Decision

1. **PNG screenshots rendered by `termshot`.** A `just screenshots`
   recipe renders `conspectus tui --snapshot` frames to PNGs under
   `docs/images/`, which the README embeds. `termshot` (nixpkgs) joins
   the dev shell; it reads the snapshot's ANSI output and draws it in
   a terminal-window frame with its bundled font. Images are committed
   and regenerated by the recipe, never by hand.
2. **The showcase world backs the previews.** A dev-only
   `conspectus dev scenario materialize <name> <dir>` writes a
   scenario's world (repos, harness transcripts, workspaces) into
   `<dir>` and keeps it. `--snapshot-fixture-root <dir>` makes snapshot
   mode read a fixture's `/fixture/...` preview paths from `<dir>`, so
   transcripts, listings, and git output are real while the frame keeps
   the fixture's paths. Running the snapshot with `HOME=/fixture`
   shortens those paths to `~/...`.
3. **A pinned clock.** `--snapshot-now <epoch>` fixes the time snapshot
   mode renders ages against. The recipe passes the showcase's anchor
   time (ADR 0070), so ages read as authored.
4. **The showcase carries conversations.** The sessions the README
   frames select get a short, realistic transcript in the showcase
   builder, so the session preview shows a conversation.

## Consequences

- The README shows what the TUI looks like, and regenerating it is one
  command that changes only when the renderer or the showcase does.
- The dev shell gains `termshot` (2 MiB). It is a documentation tool
  only; neither the build nor CI depends on it.
- `termshot`'s bundled font lacks a few symbols the TUI uses (`⚠`), so
  those cells render as boxes. The recipe accepts this rather than
  patching glyphs; a font option upstream would remove it.
- The snapshot flags stay dev-only (`--features snapshot`), like the
  rest of ADR 0067.

## Alternatives Considered

- **Keep text frames.** No tooling, but monochrome, and still needs the
  fixture work to show previews.
- **An SVG writer in the snapshot tool.** No new tool, and text stays
  selectable, but alignment depends on the reader's monospace font, so
  box drawing can drift in some browsers.
- **`freeze` (charmbracelet).** Crashed or hung on a full TUI frame.
- **VHS animated recordings.** Show navigation and suit a talk, but
  pull in Chromium, ttyd, and ffmpeg and vary run to run. Still open
  for talk material.
- **Check transcripts into `tests/fixtures/`.** Keeps the fixture
  self-contained, but duplicates what the showcase builder already
  writes and drifts from it.
- **Display the materialized world's real paths.** Simpler, but the
  frames would show temp directories.
